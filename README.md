# Demo Samples

Three synthetic ID card images for rehearsing and running the live SIH26188
pitch without any real PII and without depending on a live internet
connection to find/download test images.

Every field on these cards is a clearly-labeled placeholder ("DEMO CITIZEN",
`0000 0000 0000`, etc.) and each card is watermarked **"SPECIMEN — NOT A
REAL DOCUMENT."** They were generated by `scripts/seed_demo_samples.py` —
regenerate them anytime with:

```bash
python scripts/seed_demo_samples.py
```

## The three samples

| File | Demonstrates | Expected result |
|---|---|---|
| `sample_clean.jpg` | A clean, well-lit, single-generation JPEG | High trust score, verdict **Genuine**, no ELA regions flagged, no compression warning |
| `sample_tampered_dob.jpg` | A localized splice over the DOB field | ELA flags ~2 regions around the DOB line, visible on the heatmap overlay, trust score drops, verdict **Suspicious**/**Fake** depending on configured thresholds |
| `sample_whatsapp_forward.jpg` | An image put through several rounds of resize + low-quality re-save (simulating a forwarded photo) | `compression_warning: true` with the amber advisory banner in the UI — tamper_score alone stays low, which is the point: the warning contextualizes it |

These were verified end-to-end against the actual `ela_detector` and
`ocr_engine` modules, not just eyeballed — see the module docstrings for
the underlying mechanics (`backend/app/services/ela_detector.py`,
`backend/app/services/ocr_engine.py`).

## Running the 3-minute pitch

A suggested flow, assuming `docker compose up --build` is already running
and you've done the pre-flight checklist (see `PREFLIGHT.md`):

1. **Open the dashboard** at `http://localhost:5173`. Point out the header's
   live backend health indicator — it's actually polling `/api/v1/health`,
   not a static icon.

2. **Drop in `sample_clean.jpg`.** Narrate the auto-crop/deskew preview
   appearing, then the Trust Score gauge landing high with verdict
   **Genuine**. Toggle the ELA heatmap on the forensic viewer — clean and
   uniform, nothing flagged.

3. **Drop in `sample_tampered_dob.jpg`.** This is the key visual moment:
   toggle the heatmap and point out the DOB field lighting up distinctly
   against the rest of the card, with the targeting-bracket overlay marking
   the flagged region. Trust score drops, verdict moves to
   **Suspicious**/**Fake**. Open the Signal Breakdown panel to show the ELA
   tamper score specifically, separate from OCR/face-match.

4. **Drop in `sample_whatsapp_forward.jpg`.** This is the "why we didn't
   just threshold on ELA alone" moment: the amber compression-warning
   banner appears, explaining that heavy pre-compression (e.g. a forwarded
   photo) makes ELA's own signal less reliable here, and that the fused
   score leans on OCR/face-match more heavily as a result. This is the
   detail that shows the judges you thought about false positives, not
   just the detection happy path.

5. **Download the PDF inspection report** on any of the three, to show the
   audit trail / paper-trail feature closing the loop for an officer's
   workflow.

If time allows, mention the `/samples` + seed script exist specifically so
the demo never depends on network access or a real ID photo being on hand
— a deliberate reliability choice for a live pitch.
